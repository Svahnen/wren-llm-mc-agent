# voice/ : Wren's ears and mouth (speech service)

Listens to players near Wren (streaming STT, one stream per speaker uuid) and speaks for her (Kokoro TTS), in near-real time.
Client of the Fabric voice mod's WebSocket (mod = SERVER on `ws://127.0.0.1:19520`), local HTTP API for the bot-side mindlink.
Zero npm dependencies (Node >= 22: built-in `WebSocket`, `fetch`, `node:test`); Python only for the two model servers on the model server.

## What runs where
| piece | where | port | notes |
|---|---|---|---|
| Kokoro-82M TTS (`box/tts_server.py` + `tts_backends/`) | model server `~/wren/voice/` | 19411 (box loopback) | GPU, +1.1 GB VRAM, voice `af_heart`, `TTS_EXPRESS=0` |
| sherpa-onnx streaming STT (`box/stt_stream_server.py`, a NeMo int8 transducer model) | model server, CPU only, `nice 5` | 19412 (box loopback) | `STTS_ENDPOINT_S=3.0` so OUR endpointing decides, not the server's 0.6 s rule |
| SSH tunnel `tunnel.sh` (supervised, backoff 2..30 s) | this machine | 19411, 19412 | same pattern as `scripts/tunnel-start.sh` |
| voice service `src/main.js` (supervised by `supervise.sh`) | this machine | HTTP 127.0.0.1:19521; WS client -> 19520 | reconnects to the mod with backoff 0.5..10 s |

Why the service runs next to the Minecraft server: the mod's WebSocket is on that machine's loopback, there is no Node on the box, and only audio + text cross the tunnel (16 kHz in as it arrives to STT, ~1.5 s of text/audio out per sentence). A tunnel drop only pauses STT/TTS; the service and its HTTP API stay up and STT streams reconnect.

## Security and privacy of the voice stack
- **Mod WebSocket**: shared secret (`WRENVOICE_SECRET` here = `secret` in the mod's `wrenvoice.json`, generated by the mod on first start), browser `Origin` refused, loopback only. See [voice-mod/README.md](../voice-mod/README.md).
- **Speech servers** bind `127.0.0.1` by default (`COMPANION_BIND`); reach a remote one through the SSH tunnel. If you bind elsewhere, set `COMPANION_API_KEY` on the server and the same value as `COMPANION_API_KEY` in `voice/secrets.env`: the service then sends it as `X-API-Key` to TTS, streaming STT and second-pass STT. Generate keys with `openssl rand -hex 24`. The speech servers also refuse every request that carries an `Origin` header (browsers), so a web page cannot use them even without a key.
- **SSH**: `run.sh`, `tunnel.sh` use `BatchMode=yes` and the ssh default host-key policy: connect once by hand (`ssh $GPU_BOX`) to accept the host key, otherwise they fail with "box unreachable".
- **What is stored**: `voice/archive/` (transcripts with player name, UUID, timestamps; no audio is ever stored) and `voice/logs/`. Delete them to forget. See "Privacy and consent" in the main README: tell the players, get their consent.
- Python dependencies are pinned in `box/requirements-tts.txt`, `box/requirements-stt.txt`, `box/requirements-stt-parakeet.txt` (install into your own venvs; licences and the espeak-ng GPL note are in [NOTICE](../NOTICE)).

## Start / stop (idempotent)
    export GPU_BOX=user@YOUR_AI_SERVER   # ssh target of the machine that runs the speech models (put TTS_PYTHON, STT_PYTHON, STTS_MODEL_DIR in ~/wren/voice/box.env on it)
    voice/run.sh       # copies box/ to the model server, starts TTS+STT there, opens the tunnel, starts the supervised service
    voice/stop.sh      # all of it (KEEP_BOX=1 ./stop.sh leaves the model-server processes running)
    ./supervise.sh status | ./tunnel.sh stop | ssh $GPU_BOX 'bash ~/wren/voice/box-stop.sh'
    # everything on ONE machine? skip run.sh: start the servers yourself, loopback only, from their venvs:
    #   COMPANION_BIND=127.0.0.1 PORT_TTS=19411 TTS_BACKEND=kokoro tts-venv/bin/python box/tts_server.py
    #   COMPANION_BIND=127.0.0.1 PORT_STTSTREAM=19412 STTS_MODEL_DIR=/path/to/model STTS_ENDPOINT_S=3.0 stt-venv/bin/python box/stt_stream_server.py
    # then ./supervise.sh start
Pid files: `runtime/voice-supervisor.pid`, `runtime/voice.pid`, `runtime/tunnel.pid`; box `~/wren/voice/run/{tts,stt}.pid`. Logs: `logs/voice-YYYY-MM-DD.jsonl` (every event), `logs/stdout.log`, `logs/supervisor.log`, `logs/tunnel.log`; box `~/wren/voice/logs/{tts,stt}.log`.
Env (run.sh/main.js): `WREN_RUN_ID(dev) VOICE_ARCHIVE=off VOICE_ARCHIVE_DIR VOICE_TTS_MODEL_JSON VOICE_MOD_URL VOICE_HTTP_PORT VOICE_STT_URL VOICE_TTS_URL VOICE_VOICE VOICE_BOT_NAME VOICE_SPEAK_DISTANCE(16) GPU_BOX`; secrets (env or `voice/secrets.env`): `VOICE_TOKEN WRENVOICE_SECRET COMPANION_API_KEY`.
Idle cost: service ~0% CPU / 80 MB RSS; box TTS 0% CPU (2 GB RAM, 1.1 GB VRAM), STT 0% CPU, 300 MB RAM.

## HTTP API (127.0.0.1:19521, JSON)
- `POST /speak {text, priority:'normal'|'urgent', in_reply_to?}` -> `{utt_id}`. Normal: queued (max 4, oldest dropped). Urgent: drops queued normal speech, cuts a normal utterance in progress (flush), is never cut by a player.
- `POST /flush` -> `{flushed, interrupted:{utt_id, spoken, text(=unspoken remainder), played_ms}|null}` flush everything + clear the queue.
- `GET /heard?since=<id>&wait=25` -> `[{id,uuid,name,dist,text,addressed,ts}]` final transcripts with id > since; long-polls up to `wait` s (max 55) when nothing is new. Ambient talk is included with `addressed:false`.
- `GET /status` -> `{connected_mod, mod_hello, bot_online, near[], speaking, speaking_utt, queue_ms, queue_len, unspoken, last_latency_ms:{endpoint_ms,stt_ms,tts_first_ms}, listeners[], heard_last_id}`. `unspoken` = what was cut off ({utt_id, spoken, text, why}), kept until the next cut.
- `POST /speak_distance {d}` forwards `speak_distance` to the mod (default 16 sent on every connect).

## Behaviour
- **Addressee** (`src/addressee.js`): speaker within 6 blocks, or saying her name (wren plus ASR variants; "hey run/when/rain" as a vocative) within 16 blocks -> `addressed:true`. Otherwise heard, logged, not answered (the mindlink should only react to `addressed:true`).
- **Endpointing** (`src/listener.js`, `eotRequiredMs`): energy VAD per 20 ms frame (adaptive noise floor) + wall-clock gap (the mod sends nothing while a player is silent) + `audio_end` as a floor. Silence needed: 250 ms after terminal punctuation, 500 ms without, 1000 ms after a dangling word/comma/ellipsis, never below 350 ms (the STT lags ~0.3 s and the nemo80 model emits no punctuation, so in practice 500/1000). Then `finalize` on that speaker's stream.
- **Turn-taking** (`src/turntake.js`, pure logic, no decision model; a human-like prior decides): addressed partial transcripts while she speaks are classified; filler/backchannel ("um", "yeah", "i see") never cut her; "stop"/"wait" -> `yield_now` (flush within ~0.3 s of the word); other real attempts -> prior picks continue / finish_sentence (stop after the current sentence) / yield_trail_off (flush after 300 ms) / yield_now, escalating only upward; her name -> trail/now only; **urgent lines never yield** ("stop" at most ends after the sentence); ambient talk of non-addressed players never cuts her.
- **Speaking** (`src/speaker.js`): text -> sentences (+ early first clause at the first comma if >= 3 words precede it and >= 4 follow) -> Kokoro one sentence at a time (next one synthesized while the current is sent) -> 24 -> 48 kHz (own polyphase sinc) -> `audio_out` of 100 ms (5 x 960 samples), never more than 1.2 s ahead of the estimated playhead (mod buffer limit is 2 s). `played{}` from the mod refines `ms_played`. A flush records the **unspoken remainder** (sentences not fully played).
- Protocol framing and validation: `src/protocol.js`.

## Known limits
- nemo80 STT: lowercase, no punctuation, no proper nouns ("wren" often comes out as run/ren; handled by variants + greeting rule; sherpa hotword biasing would be the real fix, not enabled). Switch to `nemo480` (punctuated, 0.56 s partial cadence) by `STTS_MODEL_DIR` in `box/box-start.sh` if text quality matters more than partial rate.
- Not tested with the real mod, real players, real accents, or Minecraft voice-chat packet jitter/loss; Silero VAD is not used (energy VAD + mod `audio_end`).
- TTS is whole-sentence (Kokoro yields a sentence at once), so first-audio = per-sentence synthesis time.

## Run archive (text + metadata only, NO audio is ever stored)
`archive/<run-id>/` (run-id = env `WREN_RUN_ID`, default `dev`; `VOICE_ARCHIVE=off` disables, `VOICE_ARCHIVE_DIR` moves the root; git-ignored). Append-only: restarting under the same run-id appends a new session, nothing is overwritten (only `MANIFEST.json` is rewritten, merged, sessions kept). Total size is logged (`archive_utt` events, `size_mb`) and kept in the manifest; a whole evening is a few hundred KB.
- `utterances.jsonl`, one row per thing she said: `utt_id` (u1.. restarts per session, so key = session+utt_id), `text`, `sentences` (exactly what was sent to the TTS), `priority`, `in_reply_to` (+ `answered`: the transcript row she answered: uuid, name, text, times), `queued_ms`, `start_ms`/`end_ms` (UTC epoch ms, first/last audio_out), `duration_ms`, `samples48k`, `first_played_ms` + `first_played_server_ms` (estimate: arrival of the first mod `played` minus its `ms_played`; server clock via the offset of the mod's `players.t`), `flushed`, `cut`, `cut_why` (yield_now, urgent_preempt, api_flush, finish_sentence, ...), `cut_by` {uuid,name,option,text}, `played_ms` (mod's last number) and `played_ms_at_cut`, `tts` {voice, emotion, speed, seeds per sentence, seed_supported}, `audio_sha256` (sha-256 of the exact 48 kHz s16le samples sent as audio_out; the audio itself is not stored). Dropped/never-spoken lines: `{dropped:true, why}`.
- `heard.jsonl`, one row per human utterance she hears (addressed or ambient, also discarded noise with `discarded:true`): `id` (= `/heard` id), `uuid`, `name`, `dist_start`, `dist_end`, `first_audio_in_ms`, `start_ms`/`end_ms` (first/last voiced frame, UTC ms), `server_start_ms`/`server_end_ms` (mod clock, from `audio_in.t`), `final_ms`, `text` (final), `partials` [{ms,text}] (timing inside the sentence), `confidence` (null: the sherpa server gives none), `addressed` + `addressed_why` (`near<=6`, `name<=16`, `ambient:no_name`, `ambient:far`, `bot_offline`, `no_text`), `overlap_utt_id` (she was speaking), `barge` {utt_id, option} (she was cut), `endpoint_ms`, `stt_ms`, `voiced_ms`.
- `MANIFEST.json`: written at start and at stop: per session pid/start/stop, counts, bytes + sha-256 of both jsonl files; `model` = `box/MODEL.json` (exact Kokoro weights sha-256, revision, config and voice hashes, library versions, GPU) and `tts` params.

### Reproducing her voice (`tools/regen.mjs`, `tools/timeline.mjs`)
- Determinism, MEASURED: plain Kokoro is NOT bit-identical for the same text+voice+speed (two runs: equal length, SNR about 19 dB, max sample diff 4013; hashes differ every call): the decoder noise source is unseeded. So the TTS server (`box/tts_server.py`) got an optional `seed` field (torch RNG seeded before the request; `/health` then says `seed:true`) and the service sends a per-sentence seed = sha-256(sentence, voice, speed, emotion), recomputable from the index. With the seed: 4 repeats with other requests in between, different texts/speeds, are bit-identical, and regen output equals the audio_out samples (sha-256 match, tested incl. a cut utterance = prefix). A speech server started from older code ignores `seed` (restart it with `box-stop.sh` then `run.sh`); until then rows say `seed_supported:false` and regen is only perceptually identical. Same GPU/library versions are needed for bit-identity (see manifest `model`); on other hardware it is the same voice, not the same bits.
- `node tools/regen.mjs <run-dir> <utt_id> --out /abs/u3.wav [--session id]` (prints sha and `matches_index`), or from nothing: `node tools/regen.mjs --text "Hello there." --voice af_heart --speed 1.0 --out /abs/x.wav`. WAV is 48 kHz mono s16le; refuses to overwrite.
- `node tools/timeline.mjs <run-dir> --out /abs/outdir [--t0 ms|ISO] [--render]`: markers for her lines (`wren-lines.csv/.json/.edl`, `wren-labels.txt` for Audacity) and for what she heard (`heard.csv/.json/.edl`, `heard-labels.txt`: start, end, speaker, text; use these to synthesize lines with a TTS voice you have the rights to use; never clone or imitate a real person's voice without their consent). Times are relative to t0 (default: earliest event) plus absolute wall and server ms. `--render` additionally writes `wren-timeline.wav`: her lines re-synthesized from the text and placed at their start times (silence between), to overlay on the ReplayMod render. Align with the video by the server-clock columns.
- `/status.listeners[].silence_ms` (added by VINT: effective silence of a speaker mid-utterance) is kept.

## VS2: second-pass STT, vocabulary fix-up, scored barge-in
**Second pass (Parakeet-TDT-0.6B-v3, box GPU, port 19413)**: `box/stt_parakeet_server.py` = (bf16, ~1.6 GB VRAM measured; `box-start-parakeet.sh` refuses below 5 GB free VRAM and falls back to CPU; `box-stop-parakeet.sh`; pid `~/wren/voice/run/parakeet.pid`; tunnel.sh now also forwards 19413; run.sh starts it, non-fatal). Measured: server 34-37 ms per utterance, 100-300 ms round trip through the tunnel. The streaming recognizer still does partials, endpointing and barge-in; after the endpoint the buffered utterance (PCM kept per listener, 300 ms pre-roll) goes to Parakeet in parallel with the stream `finalize`. If Parakeet is down/slow (4 s timeout, 10 s backoff after 3 failures) the stream text is used (`second_pass:false`). `VOICE_PASS2=off`, `VOICE_STT2_URL`.
Per utterance (`/heard` items and heard.jsonl): `text` (Parakeet + vocabulary fix-up), `text_stream`, `alternatives[{text,src}]`, `confidence` (word agreement of the two decoders, 0..1; 0.5 when only one decoder spoke; Parakeet gives no token confidences through this wrapper), `uncertain_words[]`, `corrected:bool`; heard.jsonl additionally `text_final` (Parakeet raw), `uncertain[{word,candidates,why}]`, `changes[{from,to,why}]`, `stt2_ms`, `second_pass`. `src/vocab.js`: phonetic key + edit distance against Wren, the players near (mod `players` list) and Minecraft terms. A common word (run/when/rain) becomes Wren only in a vocative position (after hey/hi/thanks, utterance start before a comma or can/will/where..., a closing ", run.") or when the decoders disagree about it; otherwise it is reported as uncertain, never silently rewritten. The mindlink passes `misheard` / `stt_corrected` to the brain; `brain/prompt.js` adds the "speech recognition can mishear names..." guidance.
**Scored barge-in** (`src/turnscore.js`, replaces the ad-hoc rules; `turntake.js` is still the text classifier): features -> weighted logits (WEIGHTS table, one row per decision, every term visible) -> probabilities for continue / finish_sentence / yield_trail_off / yield_now. Hard rules run first and cannot be outweighed or blended: fillers/hesitations (eh/ehm/eehm/uh/hmm, any odd spelling, text-less voiced bursts of any length: the streaming decoder drops "eh" sounds, so silence from the decoder is a filler, a < 400 ms burst is a cough/click) and backchannels never cut (backchannels over 1.5 s only report `duck_db:-2`, not applied: the mod protocol has no volume message); not addressed -> continue; a warning line (priority urgent, kind warning or importance >= 0.85) is never cut (a "stop" at most gives finish_sentence); stop/wait/hold on -> yield_now; a human danger shout -> yield_now; real addressed speech needs > 700 ms overlap (or her name) and then chooses finish / trail / now by score. Features: type, overlap_ms, addressed, dist, familiarity (the service's own interaction count, same curve as people.js; `POST /familiarity {name, familiarity}` lets the mindlink override), frac_spoken and words_left of her line, importance and kind of her line, `want` (= setting 0.35 + 0.5 x importance), recent cuts in 120 s (patience), whether her line is a reply to that person, loud, question/command/contradiction. Hysteresis: a cutting decision holds 1 s and only escalates afterwards (explicit stop/danger override). Evaluated on every partial change and every 300 ms while a listener is voiced during her speech, and once more on the final text.
`POST /speak` accepts `kind: warning|answer|chatter|story` and `importance: 0..1` (defaults: urgent -> warning 0.9, in_reply_to -> answer 0.5, else chatter 0.3; story 0.5); both are stored in utterances.jsonl. **Every evaluation** is appended to `archive/<run>/turn_decisions.jsonl`: features, `x` (weight inputs), per-option `components`, `logits`, `probs` (allowed options), `probs_all`, `learned`/`blended`, `rules`, `source`, `scored_action`, `action`, `held`, her `utt_id` and `played_ms`, speaker. Plug a learned model: `TurnScorer({model:{predict(features)->probs}, alpha})` or env `VOICE_TURN_MODEL=<json linear model {weights:{option:{bias, feature:w}}}>` + `VOICE_TURN_ALPHA` (default 0 = off); hard rules still apply after blending.
Tests: `npm test` (+ `test/turnscore.test.js` 58 labelled scenarios/fuzz, `test/vocab.test.js`, `test/thoughts.test.js`); `npm run test:dev` = fake-mod end-to-end on the DEV instance (mod WS 19530, HTTP 19531, `tools/dev-tunnel.sh` -> 19541 TTS / 19542 stream STT / 19543 Parakeet; pid `runtime2/tunnel2.pid`, `tools/dev-tunnel.sh stop`).
**Synthetic ASR data** `node tools/synth-asr.mjs`: 60 sentences x 5 Kokoro voices x 4 speeds, white noise 20-30 dB SNR, through the stream and Parakeet passes; writes `archive/synth/asr-confusions.jsonl` (all rows `synthetic:true`) and `wer-table.json`; audio only in a temp dir removed afterwards.
**Thoughts track** (AI1 `thoughts.jsonl`): `node tools/timeline.mjs <run-dir> --out /abs/dir [--thoughts /abs/thoughts.jsonl] [--render-thoughts]` also writes `thoughts.csv/.json/.edl/-labels.txt` as a separate track (`track=thought`, label prefix `[THOUGHT]`, duration from deterministic regeneration, `duration_src`); `--render-thoughts` writes `thoughts-timeline.wav` (thoughts only, on demand). `node tools/regen.mjs <thoughts.jsonl|run-dir> <thought_id> --out /abs/th.wav` or `--thought-row '<json>'`: same voice/speed/per-sentence seed rule as spoken lines (bit-identical once the production box TTS runs the seed code).
